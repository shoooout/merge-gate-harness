# すり抜けた不具合を検査に戻す

検査を通ってマージされた変更に不具合が見つかったということは、検査のどこかに穴がある。不具合を直すだけでは、同じ種類の不具合が次も通る。穴を特定し、次は機械的に止まるようにする。

不具合そのものの修正は、この手順の対象ではない。修正は `acceptance-first` で行う。この手順が扱うのは、検査の側の変更である。

## 1. すり抜けた変更を特定する

不具合を持ち込んだ変更を、コミットと PR の番号で特定する。推測で決めない。不具合を再現するテストを書き、そのテストがどのコミットから落ちるかで確かめる。

特定できなかった場合は、ここで止まり、利用者に報告する。持ち込んだ変更が分からなければ、どの検査をすり抜けたのかも分からない。

## 2. どこをすり抜けたかを決める

すり抜けた変更の PR の本文を読み、次のどれに当たるかを決める。根拠を PR の本文とコードの `パス:行` で示す。

| すり抜けた場所 | 見分け方 |
| --- | --- |
| 仕様 | 不具合に当たる条件が、受け入れ条件にも異常系にも書かれていない。または書かれた条件が誤っていた |
| テスト | 条件は仕様にあったが、対応するテストが、条件が満たされなくても通る |
| リスクの分類 | 人間が diff を読んでいれば気づけた変更が、読まずにマージしてよい区分になっていた |
| 手元の検査 | lint、型検査、既存のテストのどれかが検出できる種類なのに、`checks.verify` で実行されていない |
| 動作確認 | 不具合が出る操作が、PR の「動作確認の手順」になかった |
| ハーネスの対象外 | 上のどれにも当たらない。検査で防げる種類の不具合ではない |

「ハーネスの対象外」と決めた場合は、4 の報告に進む。検査を足さない。

## 3. 戻す先を選ぶ

強制力のある場所から順に検討し、最初に当てはまるものを選ぶ。下の段を選ぶときは、上の段では防げない理由を示す。

1. **CI で止まる設定。** `.merge-gate.json` の `paths.human_review`、`review_markers`、`skip_markers`、`secret_patterns`、`limits`。該当する変更が、必ず人間の確認に回るか、CI で落ちるようになる
2. **手元と CI で実行する検査。** 対象リポジトリの lint の規則、型の定義、`checks.verify` に足すコマンド
3. **テスト。** すり抜けた種類の不具合を検出する、既存の挙動を固定するテスト
4. **文書。** 対象リポジトリのエージェント向けの指示。守られなくても何も落ちないので、上の 3 つで防げない判断にだけ使う

仕様や動作確認をすり抜けた不具合は、機械的な検査に戻せないことが多い。その場合は、同じ領域のパスを `paths.human_review` に足して人間の確認に回すことを検討する。

## 4. 証拠を揃えて、利用者の判断を求める

検査を足すかどうかを決めるのは利用者である。検査は足すたびに、人間の確認に回る変更と、落ちる変更を増やす。次の 3 つを示して判断を求める。

- **効くことの証拠。** 新しい検査を、1 で特定したすり抜けた変更に対して実際に実行し、止まることを示す。実行したコマンドと出力を残す。実行できなかった場合は、できなかったと書く。効くはずだという見込みを証拠にしない
- **巻き込む範囲。** 新しい検査が、問題のなかった変更をどれだけ止めるかを、直近にマージされた変更に対して実行して示す。何件のうち何件が止まったかを書く
- **同じ種類の不具合が起きた回数。** 今回が初めてか、過去にもあったかを、履歴と issue から調べて書く。1 回だけの不具合に検査を足すと、検査が増え続ける

`.merge-gate.json` や lint の設定は、検査の強さを左右するファイルである。編集しようとすると、人間に許可を求める確認が出る。承認を得るまで編集しない。

## 5. 変更を PR にする

検査の変更は、不具合の修正とは別の PR にする。検査の設定を変える PR は、人間が diff を確認する区分になる。

PR の本文には、4 で示した 3 つをそのまま載せる。加えて、次を書く。

- すり抜けた変更の PR の番号と、2 で決めた場所
- 3 で上の段を選ばなかった場合は、その理由
- この検査を外してよくなる条件。不具合が起きえない作りに変わったら、検査は外す

## やらないこと

- 検査を緩める変更を、この手順で行わない。誤検知が多い検査を外したい場合は、利用者に相談する
- すり抜けた変更を書いたエージェントやモデルの癖を理由に、検査を足さない。足すのは、誰が書いても必要な検査だけである
